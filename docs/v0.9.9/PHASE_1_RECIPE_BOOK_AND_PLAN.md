# v0.9.9 Phase 1 — Recipe Book & Production Plan

## 目的

加工場の各設備で、

```text
何を何個使うか
何が何個できるか
何秒かかるか
現在の在庫で何回作れるか
何回分を仕込む設定か
```

を一画面で理解できるようにする。

Phase 1では、レシピ帳と仕込み計画UIを実装する。原料の自動再配置、余剰返却、完全な詰まり回復はPhase 2で行う。

# 3. 加工場画面構成

ページは次の6つへ整理する。

```text
概要
レシピ帳
製粉機
ベーカリー
完成品
スタッフ
```

## 3.1 概要

```text
加工場の流れ

1. レシピを選び、仕込み回数を設定
2. 搬入口へ素材を入れる
3. 機械が自動で加工
4. 受取口またはスタッフが完成品を回収
```

現在の停止理由も示す。

```text
製粉機：麦が2個不足
ベーカリー：完成品置き場が満杯
```

## 3.2 レシピ帳

4レシピをカード表示する。

カードには、

- 製品アイコン
- 製品名
- 必要素材アイコンと数量
- 出力数量
- 基本時間
- 現在レベルの時間
- 現在の持ち物
- 現在の倉庫
- 現在の機械入力
- 現在作れる回数
- 対応設備
- 「このレシピを設定」ボタン

を表示する。

「現在作れる回数」は、

```ts
min(
  floor((cargo + barn + machineInput) / ingredientRequirement)
)
```

の参考値とする。ただし、倉庫を利用できない設定では倉庫分を除く。

## 3.3 製粉機・ベーカリー

各ページは、

```text
運転モード
仕込み計画
必要素材目標
入力庫
加工中
完成品
停止理由
次の操作
```

を上から順に表示する。

# 4. 仕込み回数スライダー

## 4.1 基本単位

素材個数を直接自由入力するのではなく、レシピごとの「仕込み回数」を設定する。

範囲：

```text
0〜10回分
```

1回単位。

例：

```text
小麦粉
[-] 4回分 [====------] [+]

必要：麦 8個
出力予定：小麦粉 4個
```

```text
パン
[-] 3回分 [===-------] [+]

必要：小麦粉 3個、たまご 3個
出力予定：パン 3個
```

## 4.2 入力方法

- マウスドラッグ
- タップ位置
- 左右矢印
- PageUp / PageDown
- ±ボタン
- Home：0
- End：許容最大

±ボタンとスライダーの双方を用意する。

タッチ領域は44 CSS px以上。

## 4.3 容量制約

各レシピの仕込み計画から、資源別目標を合算する。

例：

```text
パン 4回分
コーンブレッド 2回分

小麦粉：4 + 2 = 6
コーンミール：2
たまご：4 + 2 = 6
合計：14 / 18
```

目標総数が入力容量を超える設定は禁止する。

UIは、

```text
入力庫 14 / 18
残り設定可能 4枠
```

と表示する。

スライダーを増やして容量超過になる場合は、

- 値を許容最大で止める
- 「入力庫容量18を超えます」と表示
- 他レシピの値を勝手に下げない

とする。

## 4.4 機械レベルとの関係

機械レベルで入力容量が増えた場合、設定可能な最大仕込み回数も増える。

レベルダウンは存在しないため、既存計画が容量超過になる通常経路はない。

旧セーブ移行時のみ、既存在庫と計画の不一致をPhase 2の余剰診断で扱う。

# 5. 運転モードと仕込み計画

## 5.1 単品優先

例：

```text
小麦粉優先
```

小麦粉の仕込み回数が1以上なら、小麦粉を優先する。

他レシピの仕込み回数が0なら、その素材を入力目標へ含めない。

## 5.2 自動

自動では、仕込み回数が1以上のレシピだけを候補にする。

候補選択：

1. 現在開始可能
2. 計画に対して完成数が少ない
3. round-robin

固定で最初のレシピだけを選び続けない。

## 5.3 停止

停止中でも、

- レシピ帳
- 計画変更
- 入力整理
- 完成品回収

は可能とする。
