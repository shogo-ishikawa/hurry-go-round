# v0.9.9 加工場の根本原因

## 1. レシピ情報は存在するが、操作導線と結び付いていない

`RECIPES`には、必要素材、出力、時間が定義されている。

```text
小麦粉：麦2 → 小麦粉1
コーンミール：とうもろこし2 → コーンミール1
パン：小麦粉1 + たまご1 → パン1
コーンブレッド：小麦粉1 + コーンミール1 + たまご1 → コーンブレッド1
```

しかし、レシピは加工場管理画面の複数ページの一部に埋もれ、機械の搬入口や本体へ立ったときに直接確認できない。現地でプレイヤーが知りたいのは、

```text
ここへ何を持ってくるのか
何個入れれば何個作れるのか
今の在庫で何回作れるのか
```

である。加工場全体の概要と、製粉機・ベーカリー個別の操作を分離する必要がある。

## 2. 入力庫は「全素材で一つの容量」しか持たない

製粉機の入力容量は24、ベーカリーは18である。現在は資源別上限やレシピ別予約枠がなく、すべての素材が同じ容量を共有する。

例：ベーカリーでパンを作りたい場合

```text
入力庫容量 18
小麦粉 18
たまご 0
```

パンにはたまごが必要だが、入力庫に空きがないため、たまごを追加できない。小麦粉を戻す操作もないため、機械は永久にパンを開始できない。

同様に製粉機で、

```text
選択：小麦粉
入力：とうもろこし24
```

となれば、麦を投入できず停止する。

## 3. 手動投入は計画を持たず、許可素材を順番に1個ずつ入れる

現在の手動投入は、

```text
製粉機：麦・とうもろこし
ベーカリー：小麦粉・コーンミール・たまご
```

の許可リストをround-robinで処理する。選択中のレシピに必要か、何回分を仕込むか、既に十分入っているかは判断しない。

このため、プレイヤーが複数素材を持って搬入口へ入ると、意図しない配合で入力庫が埋まる可能性がある。

## 4. 倉庫補充も「1回分を追加できるか」しか判断しない

`refillOneProcessingCycleFromBarn`は、選択レシピの不足分を1回分だけ倉庫から移す。しかし、必要量より入力庫の空きが少なければ`full`で失敗する。

余剰素材を戻す処理がないため、

```text
必要素材不足
かつ
入力庫満杯
```

の状態を自力で解消できない。

## 5. 加工スタッフも生産計画を参照しない

加工スタッフは、

```text
完成品があれば倉庫へ移す
そうでなければ選択レシピ1回分を補充する
```

という処理を一定間隔で行う。

しかし、

- 何回分を維持するか
- どのレシピを優先するか
- 入力庫の余剰をどう処理するか
- 満杯で不足素材を入れられない場合にどう回復するか

を持たない。

さらに、スタッフ容量を取得しているものの、現状の一回分補充では実質的に容量が物流計画へ使われていない。

## 6. 「素材庫満杯」と「完成品置き場満杯」が混同されやすい

製造停止には少なくとも次の異なる原因がある。

```text
入力素材不足
入力庫の配合不良
入力庫容量不足
完成品置き場満杯
機械停止中
機械未建設
```

現行表示では、これらを十分に分離できていない。特に入力庫が満杯でも、必要素材が揃っていなければ「満杯なのに作れない」という矛盾した見え方になる。

## 7. 完成実績をレシピ別に保持していない

機械には`completedCycles`があるが、何を何回作ったかは区別しない。

例えば製粉機が10回完了しても、

```text
小麦粉10回
コーンミール10回
小麦粉6 + コーンミール4
```

のどれかは分からない。

したがって、プレイヤーへ、

```text
今回何が何個完成したか
累計で何個作ったか
最後に何が完成したか
```

を正確に表示できない。

## 8. 正しい解決は「投入個数」ではなく「仕込み計画」

素材ごとに自由な個数を設定するだけでは、パン用に小麦粉10・たまご1のような不均衡が再発する。

そこで基本操作は、レシピごとの仕込み回数とする。

例：パン4回分

```text
小麦粉 4
たまご 4
合計 8 / ベーカリー容量18
```

例：パン4回分 + コーンブレッド2回分

```text
小麦粉 6
コーンミール 2
たまご 6
合計 14 / 18
```

スライダーは「4回分」を選び、必要素材数を自動計算する。これにより、レシピとして成立しない配合を防げる。

## 9. 回復には余剰の返却が必要

新しい仕込み計画へ変更しても、既存入力庫の素材を消してはならない。

正しい回復は、

```text
既存在庫を計画と比較
→ 目標を超える分を余剰として表示
→ 余剰を倉庫へ原子的に返却
→ 不足分を手持ちまたは倉庫から補充
→ 生産再開
```

である。

旧セーブや既存プレイの資源を切り捨て、別素材へ変換、または暗黙に消費してはならない。
