# v0.9.9 Phase 2 — Smart Input & Buffer Recovery

## 目的

Phase 1で設定した仕込み計画を、実際の投入、倉庫補充、加工スタッフ、自動生産へ接続する。

次の状態を禁止する。

```text
入力庫が満杯
必要素材が不足
不要素材を戻せない
何も作れない
```

---

# 1. 目標在庫方式

各機械は、仕込み計画から計算した資源別目標を持つ。

例：製粉機

```text
小麦粉 4回分
コーンミール 2回分

目標：
麦 8
とうもろこし 4
合計 12 / 24
```

例：ベーカリー

```text
パン 4回分
コーンブレッド 2回分

目標：
小麦粉 6
コーンミール 2
たまご 6
合計 14 / 18
```

投入処理は、

```text
目標 - 現在入力庫
```

の不足分だけを扱う。

計画目標を超えて同じ素材を入れない。

---

# 2. 搬入口での一括投入

## 2.1 領域へ入った時

搬入口へ入ると、一回の原子的取引で、手持ちから目標不足分を移す。

例：

```text
目標：麦8
入力庫：麦3
手持ち：麦7

搬入口へ入る
→ 麦5を一括投入
→ 入力庫8
→ 手持ち2
```

結果：

```text
製粉機へ5個搬入しました
麦 5
```

一個ずつ160ms間隔で移さない。

## 2.2 領域内で加工が始まった時

製造開始で入力庫から素材が予約へ移り、入力庫が目標を下回った場合、プレイヤーが搬入口領域内に留まり、手持ちに素材があれば、再び不足分を一括補充する。

一フレームごとに繰り返さない。

再補充の契機：

- activeCycleが新たに開始
- input amountが変化
- planが変化
- cargoが変化

同じ状態signatureでは一回だけ実行する。

## 2.3 再入場

搬入口を離れるとarmed=trueへ戻る。

戻った時点で不足があれば、新しい一括投入を行う。

## 2.4 何も移せない場合

理由を明示する。

```text
仕込み回数が0です
必要素材を持っていません
計画分は補充済みです
入力庫を整理してください
設備が未建設です
```

# 3. 供給元設定

機械ごとに次を選べる。

```text
手持ち優先
倉庫優先
手持ちのみ
倉庫のみ
```

初期値：

```text
手持ち優先
```

## 3.1 手持ち優先

```text
手持ちから不足分
→ 残りを倉庫
```

ただし倉庫から自動的に遠隔移送するには、

- 「倉庫から補充」ボタン
- 対応スタッフ雇用済み

のいずれかが必要。

プレイヤーが搬入口へ入っただけで、遠隔の倉庫から魔法のように移送しない。

## 3.2 倉庫優先

加工スタッフが雇用済みの場合に有効。

スタッフ未雇用なら、

```text
加工スタッフを雇うと倉庫優先を利用できます
```

と表示する。

## 3.3 手持ちのみ・倉庫のみ

自動補充の供給元を限定する。

契約保護在庫など将来の予約ルールを追加できるmetadata構造にする。

---

# 4. 倉庫から計画まで補充

各機械ページへ、

```text
倉庫から計画まで補充
```

ボタンを置く。

一回の原子的取引で、目標不足分を移す。

例：

```text
目標：小麦粉6、コーンミール2、たまご6
現在：小麦粉2、コーンミール2、たまご1
倉庫：小麦粉10、たまご3

実行：
小麦粉4、たまご3を移動

残り不足：たまご2
```

結果に、

- 移動した資源別数量
- 合計
- 残り不足
- 倉庫不足

を表示する。

完全に揃わなくても、移動可能な分は一括で移す。

# 5. 入力庫の診断

純粋関数で、入力庫を次へ分類する。

```ts
interface ProcessingBufferDiagnosis {
  target: ResourceAmounts;
  current: ResourceAmounts;
  reserved: ResourceAmounts;
  deficits: ResourceAmounts;
  excess: ResourceAmounts;
  targetTotal: number;
  currentTotal: number;
  freeCapacity: number;
  canStartAnyPlannedRecipe: boolean;
  blockedReason:
    | "none"
    | "missing-input"
    | "wrong-mix-full"
    | "output-full"
    | "stopped"
    | "not-built";
}
```

## 5.1 配合不良満杯

例：

```text
ベーカリー入力庫 18 / 18
小麦粉18
たまご0

パン計画：小麦粉4、たまご4

余剰：小麦粉14
不足：たまご4
状態：配合不良で満杯
```

表示：

```text
素材庫は満杯ですが、パンに必要なたまごがありません。
余剰の小麦粉14個を倉庫へ戻すと再開できます。
```

## 5.2 出力満杯

入力の問題と分離する。

```text
入力は準備済み
完成品置き場が満杯
→ 完成品を回収してください
```

# 6. 余剰素材の返却

## 6.1 計画に合わせる

ボタン：

```text
素材庫を計画に合わせる
```

一回の原子的取引で、

1. 目標を超える素材を倉庫へ返す
2. 空いた枠へ、選択供給元から不足素材を入れる
3. 結果を再診断

する。

既存在庫を削除しない。

例：

```text
返却：小麦粉14
補充：たまご4
生産可能：パン4回分
```

## 6.2 すべて戻す

緊急操作：

```text
入力庫を空にして倉庫へ戻す
```

activeCycleの予約済み原料は戻さない。

入力バッファに残っている素材だけを全量倉庫へ戻す。

確認ダイアログを表示する。

## 6.3 手持ちへ戻す

必要なら、

```text
余剰を持ち物へ戻す
```

も提供できる。

持ち物容量を超える分は移さず、残量を表示する。

主要回復経路は容量制限のない倉庫とする。

# 7. 加工スタッフの計画連携

製粉スタッフ・製パンスタッフは、同じ仕込み計画と診断結果を利用する。

優先順位：

```text
1. 完成品置き場が満杯に近い
2. 完成品を倉庫へ一括搬出
3. 入力庫が配合不良満杯
4. 余剰を倉庫へ返却
5. 計画不足を倉庫から補充
6. 待機
```

スタッフは固定の「1回分補充」だけでなく、レベル別容量まで一括で運ぶ。

### 製粉スタッフ

```text
Lv1 8
Lv2 12
Lv3 16
```

### 製パンスタッフ

```text
Lv1 6
Lv2 9
Lv3 12
```

1回の移動で、容量内かつ計画不足分だけを複数資源混載できる。

例：パン計画の不足が、

```text
小麦粉3
たまご3
```

で製パンスタッフLv1なら、合計6個を一回で運ぶ。

資源ごとの内訳を保持し、移動中表示へ反映する。

# 8. 生産開始ロジック

`startProductionCycle`は、計画対象レシピだけを候補にする。

自動モードでは、

- targetCycles > 0
- 必要素材が揃う
- 出力に空きがある

ものから選ぶ。

選択順は、

1. 計画進捗率が低い
2. 長時間待っている
3. round-robin

とする。

同じレシピだけを永久に選び続けない。

仕込み計画は、単なる入力目標だけでなく、現在のproduction batchにおける予定完成数として扱う。

## 計画完了

設定した回数を完了したレシピは、次のいずれかを選べる。

```text
繰り返す
計画完了で停止
```

初期値：

```text
繰り返す
```

ユーザー要望の「加工して消費したら同じ個数を渡す」は、繰り返すモードで実現する。

# 9. 原子的取引

必要な純粋関数：

```text
transferCargoToProcessingTargets(...)
transferBarnToProcessingTargets(...)
returnProcessingExcessToBarn(...)
rebalanceProcessingInput(...)
emptyProcessingInputToBarn(...)
calculateProcessingDeficits(...)
diagnoseProcessingBuffer(...)
selectPlannedRecipe(...)
```

各処理は、

- changed
- reason
- moved breakdown
- total moved
- before / after
- prioritySaveRequested

を返す。

一回の操作で、

```text
一回のstate transition
一回のstate event
一回のpriority save
```

とする。
