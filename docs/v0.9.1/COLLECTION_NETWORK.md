# v0.9.1 集配ネットワーク

# 1. 目的

v0.9.0では加工場、製粉機、ベーカリーが追加されましたが、プレイヤーが自分で収穫した資源を加工場または倉庫へ運ぶ手間が残っています。

既存の麦・とうもろこし・養鶏スタッフは、それぞれ専用の生産ループを自動化します。一方、プレイヤーが手動で集めた混載資源や、複数区画から加工場へ送りたい原料をまとめて扱う共通物流がありません。

v0.9.1では、ゲーム内コインで集配設備を建て、専用スタッフを雇うことで、次の流れを自動化します。

```text
生産区画の集配ポイントへ預ける
→ 集配スタッフがまとめて積み込む
→ 加工場受入ボックスまたは倉庫へ運ぶ
→ 加工設備または倉庫へ安全に格納
```

「宅配ボックス」という日常語を参考にしますが、農場内の公開名称は次へ統一します。

```text
集配ボックス
集配所
集配スタッフ
加工場受入ボックス
```

現実の決済や有料課金を追加しません。すべてゲーム内コインによる購入です。

# 2. 建設順

## 2.1 前提

集配ネットワークは、加工場用地を解放した後に利用できます。

```text
東農地購入済み
鶏小屋購入済み
加工場用地購入済み
```

製粉機またはベーカリーが未建設でも、集配所と集配ボックスは建設可能です。その場合、加工できない資源は倉庫へ配送します。

## 2.2 集配所

建設価格：

```text
600コイン
```

施設名：

```text
集配所
```

短い補足：

```text
農場内の荷物をまとめて運びます
```

集配所には次を含みます。

- 小さな物流小屋
- 荷物置き場
- 仕分け棚
- 集配スタッフの待機場所
- 配送先を設定する掲示板
- 加工場受入ボックス
- 荷車または大型背負い箱

集配所は加工場の入口側へ配置し、製粉機・ベーカリー・倉庫へつながる道路を使える位置にします。

Facility Registryへ登録し、加工場、研修小屋、契約出荷場、顧客列、既存道路と重ならないことを検証します。

## 2.3 集配ボックス

集配所建設後、次の集配ポイントを個別に購入できます。

| 集配ポイント | 価格 | 初期容量 | 主な資源 |
|---|---:|---:|---|
| 麦畑集配ボックス | 180 | 24 | 麦 |
| 東農地集配ボックス | 260 | 28 | とうもろこし |
| 鶏小屋集配ボックス | 280 | 18 | たまご |

既存の麦集荷箱・とうもろこし集荷箱を置き換えて在庫を失わせないでください。

推奨構造：

- 既存集荷箱は生産スタッフ用として維持
- 集配機能を購入すると、同じ施設へ`集配側`の区画と旗を追加
- 論理在庫を別々にする場合も、用途が視覚的に分かるようにする

別の箱を隣へ追加する場合は、既存箱、看板、作物、操作範囲と重ならないことを必須とします。

## 2.4 加工場受入ボックス

集配所の建設時に自動設置します。

初期容量：

```text
36
```

受入可能資源：

```text
麦
とうもろこし
たまご
小麦粉
コーンミール
```

次は加工場受入ボックスへ入れません。

```text
パン
コーンブレッド
```

完成品は倉庫へ送ります。

# 3. プレイヤーによる預け入れ

プレイヤーは、生産区画の集配ボックスへ近づくと、持ち物から該当資源を1個ずつ預けられます。

## 3.1 麦畑

受け入れ：

```text
麦
```

とうもろこし、たまご、加工品は残します。

## 3.2 東農地

受け入れ：

```text
とうもろこし
```

他資源は残します。

## 3.3 鶏小屋

受け入れ：

```text
たまご
```

他資源は残します。

## 3.4 共通動作

- 1個ずつ転送
- 箱容量を超えない
- 持ち物の他資源を変えない
- プレイヤーが範囲を離れたら停止
- 箱が満杯なら停止
- 長い説明は操作開始時に消す
- 短い商品移動アニメーションを表示
- HUDと箱の物理表示を同期

中距離案内例：

```text
麦畑集配ボックス
麦を預けると集配スタッフが運びます
```

操作中：

```text
麦 12 / 24
```

床面には文章ではなく、箱＋下向き矢印＋資源アイコンを表示します。

# 4. 集配スタッフ

## 4.1 名称

```text
集配スタッフ
```

内部Role ID例：

```text
collection-courier
```

## 4.2 雇用

雇用価格：

```text
480コイン
```

前提：

```text
集配所建設済み
```

雇用場所：

- 研修小屋のスタッフ管理画面
- 集配所の求人掲示板

どちらも同じ純粋関数を使い、二重課金を防ぎます。

## 4.3 研修

| レベル | 積載上限 | 移動速度倍率 | 積込・荷下ろし間隔 | 研修費 |
|---|---:|---:|---:|---:|
| Lv1 | 10 | 1.00 | 130ms | 雇用時 |
| Lv2 | 14 | 1.15 | 105ms | 260コイン |
| Lv3 | 18 | 1.30 | 80ms | 620コイン |

研修は研修小屋で行います。

## 4.4 外観

集配スタッフは既存スタッフと区別できるデザインにします。

- 配送帽
- 作業ベスト
- 大型の箱型背負い具または小型荷車
- 資源別に見える積載物
- 空・部分積載・満載の差
- 歩行アニメーション
- 積込・荷下ろし動作
- 柔らかな影

色だけで役割を区別しないでください。

# 6. 集配元の選択

集配スタッフは、次の集配元を対象にします。

```text
麦畑集配ボックス
東農地集配ボックス
鶏小屋集配ボックス
```

選択優先順位は、単純な固定順で一か所を飢餓させないようにします。

推奨スコア：

```text
緊急度
+ 箱の充填率
+ 加工場の需要
+ 最終回収からの経過時間
- 移動距離ペナルティ
```

最低要件：

- 空の箱を選ばない
- 同じ箱だけを永続的に選ばない
- 最終回収時刻を考慮する
- 決定的なtie-breakを使う
- `Math.random()`へ依存しない

ラウンドロビンを基礎にしても構いません。

# 7. バッチ積込

一個だけ積んで長距離移動する挙動を禁止します。

出発条件：

```text
積載上限に到達
または
集配元が空になった
または
900msのまとめ待ちが終了
または
加工設備が原料不足の緊急状態
```

推奨設定：

```ts
collectionCourierDepartureDelayMs: 900
collectionCourierLoadIntervalMs: 130
collectionCourierUnloadIntervalMs: 130
```

Lv1で箱に10個以上ある場合、原則として10個積んでから出発します。

箱に3個しかない場合は、3個を積み、箱が空になった時点で出発します。

積載中にプレイヤーや別スタッフが箱を操作しても、負数を作らないよう1トランザクションずつ処理してください。

# 8. 配送先

## 8.1 配送モード

集配所で次を選べます。

```ts
type CollectionRoutingMode =
  | "auto"
  | "processing-first"
  | "barn-first";
```

日本語：

```text
自動
加工場優先
倉庫優先
```

## 8.2 自動モード

自動モードでは、次の順で判定します。

1. 加工設備が建設済みか
2. 対象レシピに必要な資源か
3. 加工場受入ボックスに空きがあるか
4. 現在の生産方針と原料保護量に反しないか
5. 加工場が停止中または満杯でないか
6. 条件を満たさなければ倉庫へ送る

## 8.3 資源別の基本配送

| 資源 | 加工場候補 | fallback |
|---|---|---|
| 麦 | 製粉機 | 倉庫 |
| とうもろこし | 製粉機 | 倉庫 |
| たまご | ベーカリー | 倉庫 |
| 小麦粉 | ベーカリー | 倉庫 |
| コーンミール | ベーカリー | 倉庫 |
| パン | なし | 倉庫 |
| コーンブレッド | なし | 倉庫 |

生産区画の箱は当面、麦・とうもろこし・たまごだけを扱います。

## 8.4 加工場優先

加工可能かつ受入可能なら、加工場へ送ります。

ただし、次の場合は倉庫へfallbackします。

- 加工場未建設
- 対応機械未建設
- 受入ボックス満杯
- 機械入力buffer満杯
- 資源が対応レシピに不要
- 生産方針が停止

## 8.5 倉庫優先

すべて倉庫へ送ります。

集配所を建てても、加工を望まないプレイヤーが利用できます。

# 9. 加工場受入ボックスと自動仕分け

## 9.1 状態

推奨：

```ts
interface ProcessingIntakeState {
  amounts: ResourceAmounts;
  capacity: number;
  roundRobinIndex: number;
}
```

初期容量：

```text
36
```

## 9.2 自動仕分け

加工場受入ボックスから、製粉機・ベーカリーのinput bufferへ1個ずつ移します。

優先：

- 現在の選択レシピ
- 自動レシピ候補
- 生産方針
- input bufferの不足量

同じ資源だけを永続的に優先しないよう、決定的なラウンドロビンを使います。

## 9.3 機械スタッフとの関係

製粉スタッフ・製パンスタッフは、次の両方を原料元として使えます。

```text
加工場受入ボックス
倉庫
```

優先順位：

```text
加工場受入ボックス
→ 倉庫
```

集配スタッフと加工スタッフが同時に操作しても、資源の二重消費を起こさないでください。

## 9.4 完成品

完成品は従来どおり、加工スタッフが倉庫へ運びます。

集配スタッフはv0.9.1では、加工機械のoutput bufferを回収しません。

# 10. 既存スタッフとの関係

## 10.1 麦の運搬スタッフ

従来の麦集荷箱→倉庫の仕事を維持します。

集配機能購入後、選択肢として次を設定できても構いません。

```text
従来どおり倉庫
集配ボックスへ格納
```

ただしv0.9.1の必須範囲では、従来どおり倉庫で問題ありません。

## 10.2 とうもろこし運搬スタッフ

従来のとうもろこし集荷箱→倉庫のバッチ運搬を維持します。

集配スタッフとの資源競合を避けるため、同一論理在庫を二者が同時に減らす場合は、純粋トランザクションを使います。

## 10.3 飼育スタッフ

餌補充と卵回収を維持します。

鶏小屋集配ボックスを建設した場合、卵の配送先を次から選べます。

```text
倉庫
鶏小屋集配ボックス
```

v0.9.1の必須要件では、プレイヤーが卵を箱へ預けるだけでも構いません。飼育スタッフ連携は、実装が安全に行える場合に追加します。

# 14. 資源不変条件

集配ネットワークの移送では、資源総量を変えません。

資源別総量へ追加：

```text
各集配ボックス
集配スタッフの積載
加工場受入ボックス
```

例：麦総量

```text
プレイヤー所持麦
+ 麦集荷箱
+ 麦スタッフ所持
+ 麦運搬スタッフ所持
+ 麦畑集配ボックス
+ 集配スタッフ所持麦
+ 加工場受入ボックス麦
+ 製粉機入力麦
+ 製粉中予約麦
+ 倉庫麦
+ 市場麦
+ 契約納品済み麦
```

変化：

- 収穫で+1
- 製粉で麦-2、小麦粉+1
- 販売・契約消費で該当資源減少
- 集配移送では不変

# 15. 長時間稼働

次を防止します。

- 一個だけ積んで長距離往復を繰り返す
- 空の箱へ移動し続ける
- 満杯の受入ボックス前で永久停止
- 未建設機械へ配送し続ける
- 倉庫fallbackを行わず詰まる
- 同じ箱だけを選び続ける
- ルート途中で資源が消える
- セーブ・ロードで積載が二重化
- 一時停止中に集配時間が進む

スタッフは、配送不能時に集配所へ戻り、公開状態を`配送先待ち`または`空き待ち`へ変更します。
