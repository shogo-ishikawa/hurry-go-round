# v0.9.1 検証・受入条件

# 1. 必須コマンド

完了前に必ず実行します。

```bash
npm ci --no-audit --no-fund
npm run check
npm run build
```

`npm run check`はTypeScript型チェックと全Vitestを含みます。

GitHub Pagesのbaseは維持します。

```text
/hurry-go-round/
```

ビルド後に確認：

- JavaScript URLが`/hurry-go-round/`で始まる
- CSS URLが`/hurry-go-round/`で始まる
- `/carry-and-thrive/`がない
- ローカル絶対パスがない
- `dist/`をコミットしていない

# 6. 集配ボックスの純粋テスト

- 正確な建設費を引く

- 他資源を変更しない
- 未建設箱へ預けられない
- 箱満杯時に変化なし

# 8. バッチ積込テスト

Lv1容量10の場合：

- source 20 → 10積む
- source 6 → 6積む
- source 0 → 積まない
- carried 8、source 20 → 2積む
- 容量を超えない

出発条件：

- 満載で即出発
- source空で現在積載ありなら出発
- 900ms経過で部分積載出発
- 積載0では出発しない
- 緊急需要時に積載ありなら出発可能

一個だけ存在する場合は一個で出発できますが、10個存在するのに一個だけ積んで出発してはいけません。

# 9. 配送先判定テスト

## 自動

麦：

- 製粉機建設済み、受入空き、需要あり → 加工場
- 製粉機未建設 → 倉庫
- 受入満杯 → 倉庫

とうもろこし：

- コーンミール需要あり → 加工場
- 加工停止・満杯 → 倉庫

たまご：

- ベーカリー建設済み、レシピ需要あり → 加工場
- ベーカリー未建設 → 倉庫

パン・コーンブレッド：

- 常に倉庫

## 加工場優先

- 受入可能なら加工場
- 不可能なら倉庫fallback
- 永久待機しない

## 倉庫優先

- 加工可能でも倉庫

# 10. 集配スタッフ状態テスト

- 未雇用ではruntimeを生成しない
- 雇用時Lv1

- fallback不能時に集配所で待機
- 負数なし
- 重複配送なし
- 同じ資源を二回荷下ろししない

# 12. 資源不変条件

各資源について、集配移送の前後で総量が一致します。

集計対象：

- プレイヤー持ち物
- 既存集荷箱
- 既存スタッフ積載
- 集配ボックス
- 集配スタッフ積載
- 加工場受入ボックス
- 機械input
- 機械reservedInputs
- 機械output
- 倉庫
- 市場
- 契約納品済み
- 餌箱・卵置き場

正規の生産・変換・販売以外で増減しないこと。

例：集配スタッフが麦10を移動：

```text
箱 -10
スタッフ +10
総量不変
```

加工場へ荷下ろし：

```text
スタッフ -10
受入 +10
総量不変
```
