# v0.9.1 用語整理と研修小屋

# 1. 目的

現行UIの「背負い籠」は、農作物だけでなく、たまご、小麦粉、コーンミール、パン、コーンブレッドまで同時に運ぶ状態を表す名称として不自然です。

また、現行の`operations-office`は第2麦畑の範囲と重なっています。

現行の代表的な範囲：

```text
第2麦畑：おおむね x=760〜1350, y=885〜1185
operations-office：x=1080〜1310, y=1000〜1150
```

研修・運営施設が作物の上へ置かれ、麦と施設の表示、移動、看板、操作範囲が競合しています。

v0.9.1では、公開用語を文脈別に整理し、研修機能を独立した小屋へ移します。

---

# 2. 公開用語

## 2.1 基本方針

内部コードでは次を維持して構いません。

```text
cargo
carryCapacity
carried amounts
```

公開UIでは、一つの英語概念を無理に一つの日本語へ固定せず、表示文脈に応じて自然な表現を使います。

## 2.2 正式表記

| 現在の表記 | v0.9.1の表記 | 使用場面 |
|---|---|---|
| 背負い籠 | 持ち物 | HUDのパネル見出し |
| 背負い籠 | 運搬かご | 物理的なかご、強化施設、説明文 |
| 背負い籠容量 | 持てる数 | HUD、設定、簡潔な説明 |
| 背負い籠を大きくする | 運搬かごを大きくする | 強化案内 |
| 背負い籠が満杯です | 持ち物がいっぱいです | 警告 |
| 背負い籠へ移す | 持ち物に加える | 受取案内 |
| 背負い籠から納品 | 持ち物から納品 | 納品案内 |

## 2.3 HUD

推奨表示：

```text
持ち物　15 / 18
麦　　　　　 7
とうもろこし  5
たまご　　　  3
```

空の場合：

```text
持ち物
空　0 / 18
```

容量アップ後：

```text
持てる数が18になりました
```

満載時：

```text
持ち物がいっぱいです
倉庫・加工場・集配ポイントへ運びましょう
```

## 2.4 強化施設

施設名：

```text
運搬かご
```

接近案内：

```text
運搬かごを大きくする
12 → 18
60コイン
```

最大時：

```text
運搬かご
持てる数 24
最大です
```

## 2.5 チュートリアル

使用例：

```text
収穫物は持ち物に加わります
持ち物がいっぱいになったら倉庫へ向かいましょう
運搬かごを強化すると、一度に持てる数が増えます
```

## 2.6 文字列管理

公開文字列を`localization.ts`または同等の集中管理へ置きます。

コード内に次を重複して直書きしないでください。

- 持ち物
- 運搬かご
- 持てる数
- 持ち物がいっぱいです
- 研修小屋
- 集配所
- 集配ボックス
- 集配スタッフ

## 2.7 検索受入条件

現行ランタイム、README、ヘルプ、v0.9.1仕様の公開文面から、現在形の「背負い籠」が0件であることを確認します。

過去のバージョン仕様書に履歴として残る「背負い籠」は許可します。

# 3. 研修小屋

## 3.1 施設名

```text
研修小屋
```

短い補足：

```text
スタッフ・研修
```

`農場運営所`を一般管理機能として残す場合でも、スタッフの雇用と研修を行う物理施設は`研修小屋`へ統一します。

推奨方針：

- マップ上の物理施設：研修小屋
- カメラ固定画面の見出し：スタッフ管理
- 既存イベント名`operationsOpen`等は内部互換のため維持可能

## 3.2 旧施設の撤去

現行の次を撤去します。

```text
operations-office
中心：おおむね x=1195, y=1075
```

撤去対象：

- 操作円
- `運営所`の裸の文字
- 施設の影・床面
- 対応看板
- wheat plotと重なる障害物

旧施設撤去後、第2麦畑の作物、畝、プレイヤー、収穫スタッフが完全に見えることを確認します。

保存データ内の施設座標は保存しません。古いセーブを読み込んでも、新しい小屋位置から再構築します。

## 3.3 配置場所

研修小屋は西側の空き地へ配置します。

優先配置：

```ts
trainingLodgeBounds = {
  x: 55,
  y: 655,
  width: 285,
  height: 210,
};

trainingLodgeEntrance = {
  x: 350,
  y: 780,
  radius: 96,
};
```

この位置は、次から離します。

- 第1麦畑
- 第2麦畑
- 池
- 市場
- 倉庫
- 契約掲示板
- 契約出荷場
- 加工場
- 鶏小屋
- 既存スタッフの主要経路

最低間隔：

```text
作物区画から80
池・建物から60
操作範囲同士40
看板同士40
世界端から30
```

実装時にv0.9.0の加工場がこの候補範囲へ実際に干渉している場合は、次の代替候補を順に検討してください。

```text
候補2：x=80〜370, y=1180〜1370
候補3：x=360〜650, y=650〜850
```

ただし、候補2は池・鶏小屋、候補3は第1麦畑・道との距離を検証し、純粋な施設配置テストで重なりがない候補だけを採用します。

座標を場当たり的に直接書き込まず、Facility Registryの定義を唯一の座標源にしてください。

## 3.4 外観

研修小屋は、操作円だけではなく、明確な建物として描きます。

構成：

- 小さな木造小屋
- 切妻屋根
- 窓
- 入口
- 掲示板
- 練習用の木箱・鎌・荷車
- 小さな旗
- 小屋へつながる脇道
- 建物の影
- `研修小屋`の木製看板

禁止：

- 麦の上へ半透明円だけ置く
- 地面に`研修`と裸の文字を置く
- 既存木や花を不自然な円で囲む
- 小屋が麦畑の収穫判定を遮る

## 3.5 アクセス

研修小屋の入口付近で次を利用できます。

PC：

```text
E
Space
カメラ固定ボタン
```

スマートフォン：

```text
スタッフ管理
```

画面を開いている間はゲームを一時停止します。

## 3.6 スタッフ管理画面

対象職種：

- 麦の収穫スタッフ
- 麦の運搬スタッフ
- とうもろこし収穫スタッフ
- とうもろこし運搬スタッフ
- 飼育スタッフ
- 製粉スタッフ
- 製パンスタッフ
- 集配スタッフ

各カードに表示：

```text
職種名
雇用済み／未雇用
現在レベル
現在の作業
積載量
次の研修効果
雇用・研修価格
前提条件
```

地図上で個別スタッフの研修看板を大量に置かないでください。

## 3.7 雇用と研修の責務

研修小屋は、スタッフの雇用・研修を行う一つのUI入口です。

現地の雇用パッドを維持する場合でも、次を共通化します。

```text
getWorkerAvailability
hireWorkerByRole
getWorkerTrainingCost
trainWorker
```

研修小屋と現地パッドで異なる価格、条件、レベルを使わないでください。

一つの操作で二重にコインを引かないでください。

成功時は優先自動保存を要求します。

## 3.8 表示状態

未解放：

```text
東農地を購入すると雇用できます
鶏小屋を購入すると雇用できます
加工場を建てると雇用できます
集配所を建てると雇用できます
```

コイン不足：

```text
あと 120 コイン必要です
```

雇用済み：

```text
雇用済み　Lv1
```

最大研修：

```text
Lv3　最大
```

## 3.9 施設Registry

推奨追加・変更：

```ts
type FacilityId =
  | ...
  | "training-lodge"
  | "collection-hub";
```

旧`operations-office`は、v0.9.1ランタイム施設一覧から外します。

互換用に古い保存値・UI選択IDを受け取った場合：

```text
operations-office → training-lodge
```

へ正規化するか、安全に`null`へ戻します。

## 3.10 看板

研修小屋の看板は、小屋の入口脇へ一枚だけ置きます。

```text
研修小屋
スタッフ・研修
```

職種ごとの大型看板を周囲へ置かないでください。

看板と入口操作範囲、脇道、建物、世界端が重ならないことをテストします。


- HUD見出しが`持ち物`

# 5. テスト要件

純粋テスト：

- 用語マッピングが文脈別に正しい
- 旧施設IDを新施設IDへ正規化できる
- 研修小屋の矩形が第1・第2麦畑と重ならない
- 研修小屋が池・加工場・鶏小屋と重ならない
- 入口操作範囲が到達可能
- 看板が建物と重ならない
- 雇用・研修が一度だけ課金する
- 未解放職種を雇用できない
- 成功時に優先保存を要求する

回帰テスト：

- 麦畑上に`operations-office`が残らない
- wheat crop node数が移設前後で変わらない
- 研修小屋へ移してもスタッフの雇用・研修が機能する
- 既存セーブのスタッフ雇用・レベルが維持される
