# 4. 保存リリース阻害テスト

## 4.1 validator

### 整数必須

- 資源数
- コイン
- 容量
- レベル
- 契約個数

へ小数を与えると失敗します。

### 小数時間を許容または正常化

- `remainingMs = 1234.56`
- `playTimeMs = 98765.432`
- `waitMs = 700.25`

を含む正常snapshotが、canonicalization後に保存できます。

### 異常値

- NaN
- Infinity
- -1

を拒否します。

## 4.2 repository round-trip

1. snapshot作成
2. checksum作成
3. primary保存
4. primary読込
5. checksum検証
6. schema検証
7. restore
8. 再snapshot
9. 重要フィールド比較

## 4.3 backup

- 正常primaryをbackupへ回す
- 新primary破損時にbackup復旧
- backup復旧を画面表示

## 4.4 localStorage fallback

- IndexedDB open失敗
- IndexedDB transaction失敗
- quota失敗

を模擬し、簡易保存へ切り替えます。

簡易保存から再読込できます。

## 4.5 保存キュー

- 保存中にdirty
- 保存中にpriority dirty
- 連続購入
- 連続雇用

で最新状態が最終的に保存されます。

要求が失われないことを確認します。

## 4.6 saveSequence

- schema 4からsequence 45を読込
- 次回保存で46
- 0や1へ戻らない

## 4.7 手動保存UI

- ボタン押下で「保存中…」
- 成功で「保存しました」
- 時刻を表示
- 失敗で「保存に失敗しました」
- 再試行ボタン
- JSON書き出し導線
- overlay内で結果が見える

## 4.8 保存テスト機能

- 成功時にbackend表示
- 失敗時に理由表示
- 実際にrepositoryへ書いて読み戻す
- UIだけ成功表示する偽テストにしない
